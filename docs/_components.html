Components

Everything you can use inside a Markdown page. Defined in content/components.html.

Note

Neutral context the reader should know. Optional title.

Before you start

You need a workspace and a calling line. Your account team sets both up.

Markdown
<Note title="Before you start">You need a workspace and a calling line. Your account team sets both up.</Note>

Tip

A shortcut or good practice.

Start with 20 to 50 rows and listen to the first calls before you upload the full list.

Markdown
<Tip>Start with 20 to 50 rows and listen to the first calls before you upload the full list.</Tip>

Info

Availability, plan or setup information.

Available on enterprise workspaces. Your account team switches it on.

Markdown
<Info>Available on enterprise workspaces. Your account team switches it on.</Info>

Warning

Something that costs money, calls real people or cannot be undone.

This starts real calls

Confirming the upload dials every row that passes the compliance checks.

Markdown
<Warning title="This starts real calls">Confirming the upload dials every row that passes the compliance checks.</Warning>

Check

A success state or a checklist outcome.

Your agent is ready to call.

Markdown
<Check>Your agent is ready to call.</Check>

Soon

Marks something that is not in the product yet. Optional title (default "Coming soon"). For a whole page, set status: soon in its frontmatter instead.

Coming soon

Event triggers start a call when a record changes in your ERP. Ask your account team for early access.

Markdown
<Soon>Event triggers start a call when a record changes in your ERP. Ask your account team for early access.</Soon>

Badge

A small label inside a sentence, heading or table. tone: new, live, preview, enterprise, soon.

Sheet automation Enterprise and the API Coming soon.

Markdown
Sheet automation <Badge tone="enterprise">Enterprise</Badge> and the API <Badge tone="soon">Coming soon</Badge>.

Method

An HTTP method label. name: GET, POST, PATCH, PUT, DELETE.

POST creates a call, GET reads it.

Markdown
<Method name="POST"/> creates a call, <Method name="GET"/> reads it.

Term

Explains a term or abbreviation on hover and for screen readers. Good for jargon and keywords.

Every number is checked against the DND list.

Markdown
Every number is checked against the <Term tip="India's Do Not Disturb registry for commercial calls">DND</Term> list.

CardGroup

A grid of Cards. cols: 1 to 4 (default 2).

Get startedQuickstart

Your first campaign in about fifteen minutes.

 DevelopersWebhooks

Outcomes pushed to your system.

Markdown
<CardGroup cols="2">
<Card title="Quickstart" href="quickstart" eyebrow="Get started">Your first campaign in about fifteen minutes.</Card>
<Card title="Webhooks" href="../developers/webhooks" eyebrow="Developers">Outcomes pushed to your system.</Card>
</CardGroup>

Card

A linked card. title, href, optional eyebrow.

LaunchCampaigns

Upload a sheet and call every row.

Markdown
<Card title="Campaigns" href="campaigns" eyebrow="Launch">Upload a sheet and call every row.</Card>

Columns

Side-by-side blocks. Put each block in a Column.

Inputs. What the agent knows before the call.

Outputs. What it must report after.

Markdown
<Columns>
<Column>
**Inputs.** What the agent knows before the call.
</Column>
<Column>
**Outputs.** What it must report after.
</Column>
</Columns>

Column

One cell of Columns.

Any Markdown.

Markdown
<Column>Any Markdown.</Column>

Steps

A numbered procedure. Each Step has a title.

  1. Create an agent

    Go to Agents → New agent.

  2. Test it

    Open the Call console and start a browser call.

Markdown
<Steps>
<Step title="Create an agent">Go to **Agents → New agent**.</Step>
<Step title="Test it">Open the **Call console** and start a browser call.</Step>
</Steps>

Step

One step inside Steps.

  1. Upload the list

    Press Upload data.

Markdown
<Steps><Step title="Upload the list">Press **Upload data**.</Step></Steps>

Tabs

Switchable panels. Each Tab has a title. Without JavaScript every panel shows, so search engines read all of it.

Upload a sheet in Campaigns.

Call POST /v1/campaigns.

Markdown
<Tabs>
<Tab title="No code">Upload a sheet in **Campaigns**.</Tab>
<Tab title="API">Call `POST /v1/campaigns`.</Tab>
</Tabs>

Tab

One panel inside Tabs.

Content.

Markdown
<Tabs><Tab title="Only tab">Content.</Tab></Tabs>

Accordion

A collapsible section. title, optional open flag.

What happens if the supplier asks for a call back?

The agent books the time and the call is retried then.

Markdown
<Accordion title="What happens if the supplier asks for a call back?">The agent books the time and the call is retried then.</Accordion>

AccordionGroup

Stacks Accordions with shared borders.

First question

Answer.

Second question

Answer.

Markdown
<AccordionGroup>
<Accordion title="First question">Answer.</Accordion>
<Accordion title="Second question">Answer.</Accordion>
</AccordionGroup>

Frame

Frames a screenshot, diagram or mock screen, with a caption. Plain images with a title get the same frame automatically: ![Alt](assets/x.png "Caption").

Markdown
<Frame caption="The call console with a live transcript.">
![Call console](assets/placeholder.svg)
</Frame>

CodeGroup

Several code blocks as tabs. The text after the language names the tab: ```bash cURL

cURL
curl "$ECHO_API/v1/agents" -H "Authorization: Bearer $ECHO_API_KEY"
Python
requests.get(f"{API}/v1/agents", headers=HEADERS)
Markdown
<CodeGroup>
```bash cURL
curl "$ECHO_API/v1/agents" -H "Authorization: Bearer $ECHO_API_KEY"
```
```python Python
requests.get(f"{API}/v1/agents", headers=HEADERS)
```
</CodeGroup>

Endpoint

An API operation. method, path, title. Put the description and Params on the left; RequestExample and ResponseExample go to the right column.

POST/v1/calls

Place a call#

Dials one number with an agent.

Body#

agentstringrequired

Agent id.

cURL
curl -X POST "$ECHO_API/v1/calls" -H "Authorization: Bearer $ECHO_API_KEY"

Response · 202

JSON
{ "id": "call_8f2k1q", "status": "queued" }
Markdown
<Endpoint method="POST" path="/v1/calls" title="Place a call">
Dials one number with an agent.

<Params title="Body">
<ParamField name="agent" type="string" required>Agent id.</ParamField>
</Params>

<RequestExample>
```bash cURL
curl -X POST "$ECHO_API/v1/calls" -H "Authorization: Bearer $ECHO_API_KEY"
```
</RequestExample>
<ResponseExample status="202">
```json
{ "id": "call_8f2k1q", "status": "queued" }
```
</ResponseExample>
</Endpoint>

Params

A titled list of fields: Body, Query, Path, Headers, Response.

Query#

limitintegerdefault 50

Up to 200.

Markdown
<Params title="Query">
<ParamField name="limit" type="integer" default="50">Up to 200.</ParamField>
</Params>

ParamField

One field. name, type, optional required flag and default.

tostringrequired

E.164 number.

Markdown
<ParamField name="to" type="string" required>E.164 number.</ParamField>

ResponseField

A field in a response object. Same props as ParamField.

statusstring

queued, dialling, completed or failed.

Markdown
<ResponseField name="status" type="string">queued, dialling, completed or failed.</ResponseField>

```bash cURL
curl "$ECHO_API/v1/calls/call_8f2k1q" -H "Authorization: Bearer $ECHO_API_KEY"
```
</RequestExample>
